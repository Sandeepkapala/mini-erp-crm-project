# Mini ERP + CRM Operations Portal

A full-stack case-study implementation for a wholesale/distribution company. It covers authentication and role-based access, CRM customers/follow-ups, products and inventory, stock movement logging, and sales challans with transactional stock reduction.

## Stack
- Backend: Node.js + TypeScript + Express + PostgreSQL + REST + Zod + JWT
- Frontend: React + TypeScript + Vite + CSS
- Deployment targets: Vercel/Netlify/Render frontend; Render/Railway backend; Supabase/Neon/Render Postgres database

## Requirement coverage
- Authentication: Admin, Sales, Warehouse, Accounts roles with JWT.
- Customer CRM: add, edit API, search, detail, follow-up notes.
- Product/inventory: add/edit API, stock levels, low-stock alert, stock movement endpoint.
- Sales challan: automatic number, multiple products, draft/confirmed/cancelled status, product snapshot, transaction + row locking, insufficient-stock validation, no negative stock.
- API: validation, status codes, errors, pagination/search for customers.
- UI: responsive admin-style dashboard.
- Environment variables and local setup documented.

## 1. Database
Install PostgreSQL and create a database named `mini_erp_crm`.

Run `database/schema.sql` in that database.

## 2. Backend
```bash
cd backend
npm install
copy .env.example .env
```

Windows PowerShell alternative:
```powershell
Copy-Item .env.example .env
```

Edit `.env` with your PostgreSQL connection string and JWT secret.

```bash
npm run seed
npm run dev
```

Backend: `http://localhost:5000`
Health: `http://localhost:5000/api/health`

## 3. Frontend
```bash
cd frontend
npm install
copy .env.example .env
npm run dev
```

Frontend: Vite will show the local URL, normally `http://localhost:5173`.

- PUT `/api/products/:id`
- GET `/api/products/:id/movements`
- GET/POST `/api/challans`
- GET `/api/challans/:id`

All protected endpoints use `Authorization: Bearer <JWT>`.

## Challan business logic
Confirmed challans run inside a PostgreSQL transaction. Product rows are locked with `FOR UPDATE`, stock is checked before the sale, challan items store product name/SKU/unit-price snapshots, and OUT movements are recorded. If any item is short, the transaction is rolled back and a 409 error is returned.

## Deployment
For a free deployment, create a hosted PostgreSQL database on Supabase, Neon, Render or similar. Deploy the backend to Render/Railway/Fly.io and set `DATABASE_URL`, `JWT_SECRET`, `CORS_ORIGIN`, and `PORT`. Deploy the frontend to Vercel/Netlify/Render Static Site and set `VITE_API_URL` to the deployed backend `/api` URL.

## Assumptions / limitations
- Accounts role is authenticated and can access the portal, but invoice/accounting screens were not requested as a core module.
- Product edit and customer edit are implemented in the API; the compact UI focuses on the core create/search/detail flow.
- Stock IN UI is not exposed; stock movement logging is generated by confirmed challans, while the movement API is available for warehouse integrations.
- PDF invoice, S3 product images, Docker and GitHub Actions are intentionally left as bonus extensions.
